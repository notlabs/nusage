# The catalog

Typed Nushell commands for other tools, each generated by nusage from the tool's usage spec,
the schemas of its outputs and the overlays kept beside it. One module package per tool under
`lib/`; the entries in `mise.toml` under `[_.nusage.catalog]`; the tasks that make and check
them in `tasks/`, whose `catalog.nu` documents the package layout; beside them `clap/`, which
reads the spec of a binary whose crate builds its clap command; [`cobra/`](cobra/README.md),
which reads a command tree from a pinned Go module; and `schemas/`, the runner of
an output-schema suite.

## Use it

The catalog is released as the `nusage-catalog` tool, from this repository's `catalog/v*`
tags. The conf.d fragment `nusage/conf.d/nusage.toml` installs it with nusage and puts its
`lib` on `$NU_LIB_DIRS`, so every Nushell that starts under mise's environment finds the
modules:

```nu
use mise *
mise tasks ls | where name =~ check
use jj *
jj log --revision ["@"]
```

A project pins it the same way, with `tools = true` on the variable because its value needs
the tool installed:

```toml
[tool_alias]
nusage-catalog = "github:notlabs/nusage"

[tools]
nusage-catalog = { version = "0.1.0", version_prefix = "catalog/v", bin_path = "bin" }

[env]
NU_LIB_DIRS = { value = "{{ tools['nusage-catalog'].path }}/lib", tools = true }
```

Nushell reads `NU_LIB_DIRS` when it starts, and `mise activate` sets the environment at the
prompt, after the shell started: a script, `mise run`, `mise exec` and a new shell see it,
the shell you activated in does from its next start. For a new interactive session to load
the modules unasked, `mise run //catalog:install` here writes one `use` line per entry into
Nushell's user autoload directory, and the release's `autoload/` directory holds the same
lines for a vendor autoload directory.

### Editors

An editor starts `nu --lsp` itself, before any shell. A mise command wrapper gives it the
project's environment: it keeps the name `nu`, so the editor's configuration does not change,
and delegates to `nusage nu`, which serves nusage's language server for `--lsp` and runs the
real `nu` for anything else, so a project wrapper and the global one nusage's conf.d fragment
offers behave alike. `mise reshim` after adding it, and put mise's `command-wrappers/bin`
directory, which `mise activate` adds to `PATH`, on the editor's `PATH`:

```toml
[wrappers.nu]
command = "nusage"
args = ["nu"]
env = { NU_LIB_DIRS = "{{ [config_root, '.nusage', 'lib'] | join_path }}" }
```

A wrapper's values see `config_root`, `vars` and the environment, not the installed tools,
so point it at a directory the project owns. The wrapper needs a nusage release that has
`nusage nu`; an older one rejects the subcommand, and with it every `nu` the wrapper starts.

### The tasks elsewhere

The tasks are pushed to GHCR as an OCI task catalog, so a project with its own
`[_.nusage.catalog]` entries regenerates modules against the tool versions it pins, without
this repository:

```toml
[task_config]
includes = ["oci::ghcr.io/notlabs/nusage-tasks:0.1.0"]
```

They run as `catalog:spec`, `catalog:generate`, `catalog:check` and `catalog:install`, and
need `nusage`, `nu` and `usage` on `PATH`, as the conf.d fragment installs them. Pin a
digest, `@sha256:…`, where a moved tag must not pass unnoticed.

## Add an entry

1. Declare it in `mise.toml`: `spec = { run = "…" }` names a command line that prints the
   tool's usage spec, `spec = { clap = "spec" }` an extractor under the package that
   `clap/spec.nu` builds and runs, as `clap/README.md` describes, or `spec = { openapi =
   "openapi.yaml" }` the OpenAPI document of a service under the package, as
   `lib/typesafe/` has it; `switch` names the flag that selects structured output and its
   framing, when the spec declares no `output`. A `run` whose export builds something adds
   `probe = "version"`, so `check` compares the spec's `version` to `<bin> --version` rather
   than exporting again.
2. `mise run //catalog:spec <tool>` writes `lib/<tool>/<tool>.usage.kdl`; for a service also
   `<tool>.http.kdl`, the mapping the wrappers send requests by, and `schemas/`.
3. Add `lib/<tool>/*.overlay.kdl` for what the spec lacks: types, outputs, selectors. They
   merge in name order after the generated overlays. A suite under `lib/<tool>/schemas/`,
   as `schemas/README.md` describes, declares outputs with their schemas instead, and
   `lib/<tool>/check-schemas.nu` holds the tool's raw output to it.
4. `mise run //catalog:generate <tool>` writes `lib/<tool>/mod.nu`; commit it with the spec.
5. Add `lib/<tool>/check.nu`, which `check` runs with `lib` included: `use <tool> *`, then
   drive the tool and assert on what comes back. Add `lib/<tool>/nupm.nuon`.

`mise run //catalog:check` holds every entry's committed files to its inputs and its spec to
the tool on `PATH`.

## Release

Bump `catalog_version` under `[vars]` in `mise.toml` and merge. The push to main that changes
it is the release: `release.yml` runs `//catalog:package`, pushes the tasks to
`ghcr.io/notlabs/nusage-tasks:<version>`, and creates the `catalog/v<version>` release with
`nusage-catalog-<version>.tar.gz` attached.
