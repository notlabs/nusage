# The catalog

Typed Nushell commands for other tools, generated by nusage from each tool's usage spec, the schemas of its outputs and the overlays beside it: a module package per tool under `packages/`, entry metadata in each package's `mise.toml` under `[_.nusage.catalog]`, and the tasks that make and check them in `mise-tasks/`, where `lib/catalog.nu` says what an entry declares and what a package holds.

## Use it

Each entry with a `version` is released as the packslip package `github.com/notlabs/nusage/catalog/<tool>`, which records the mise tool and version its spec was read from.
A project installs the packages it uses, pins the tools they wrap at those versions, and includes nusage's fragment:

```toml
include = ["git::https://github.com/notlabs/nusage.git//nusage/conf.d/nus.toml?ref=v<nusage>"]

[tools]
"github:notlabs/nusage" = { version = "<nusage>", version_prefix = "v" }
"packslip:github.com/notlabs/nusage/catalog/jj" = "<package>"
jujutsu = "<the version the package records>"
```

A script then calls the commands without importing them:

```nu
#!/usr/bin/env nus
jj log --revision ["@"] | first | get change_id
```

A call whose first word is a package's gets `use <module> *` before the script; a package whose tool the project has at another version than it was generated from is refused, and `^jj` is still the binary.
The include also makes `nu` the `nus nu` wrapper; run `mise reshim` after adding it.
An interactive Nushell gets the packages from `nus activate nu`, as the root README describes.

The tasks are also published as the OCI task catalog `ghcr.io/notlabs/nusage-tasks`, for a monorepo with its own discovered entry projects and `[_.nusage.catalog]` metadata: `[task_config] includes = ["oci::ghcr.io/notlabs/nusage-tasks:<version>"]`.
They need `nus`, `nu` and `usage` on PATH; a `clap` entry also Cargo and rustfmt, an `openapi` entry `openapi-usage`.

## Release

A checked main commit releases each entry whose `catalog/<tool>/v<version>` has no release yet: the archive `//catalog:pack` writes, and its packslip signature.
When `catalog_version` under `[vars]` has no `catalog/v<version>` release, the task catalog is pushed to GHCR at that version.

Each entry owns `spec`, `generate`, `check`, and `check:platform` tasks, by including the shared `packages/package.tasks.toml` definitions.
For example, `mise exec -- mise run //catalog/packages/jj:spec --force` refreshes jj's spec and `mise exec -- mise run //catalog/packages/jj:generate` regenerates its module.
The catalog-wide `spec` and `generate` tasks select `./packages/...` tasks through Mise; adding an entry requires no parent registry edit.
`//catalog:check` checks the catalog's own implementation and package interfaces.
Use `mise exec -- mise run '//catalog/...:check'` to check the whole subtree.
An entry depends on the generator its spec names and on what its Nushell loads, which the project graph derives; its included check task uses `^check` to validate those projects before the entry.
Platform checks use `^check:platform` so they retain the upstream platform-specific scope.
The `nus` the tasks run is the root's `nus` provider's build, on PATH.
