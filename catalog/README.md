# The catalog

Typed Nushell commands for other tools, generated by nusage from each tool's usage spec, the schemas of its outputs and the overlays beside it: a module package per tool under `lib/`, an entry per package in `mise.toml` under `[_.nusage.catalog]`, and the tasks that make and check them in `tasks/`, where `catalog.nu` says what an entry declares and what a package holds.

## Use it

Each entry with a `version` is released as the packslip package `github.com/notlabs/nusage/catalog/<tool>`, which records the mise tool and version its spec was read from.
A project installs the packages it uses, pins the tools they wrap at those versions, and includes nusage's fragment:

```toml
include = ["git::https://github.com/notlabs/nusage.git//nusage/conf.d/nus.toml?ref=v<nusage>"]

[tools]
"github:notlabs/nusage" = { version = "<nusage>", version_prefix = "v" }
"packslip:github.com/notlabs/nusage/catalog/jj" = "<package>"
jujutsu = "<the version the package records>"
```

A script then calls the commands without importing them:

```nu
#!/usr/bin/env nus
jj log --revision ["@"] | first | get change_id
```

A call whose first word is a package's gets `use <module> *` before the script; a package whose tool the project has at another version than it was generated from is refused, and `^jj` is still the binary.
The include also makes `nu` the `nus nu` wrapper; run `mise reshim` after adding it.
An interactive Nushell gets the packages from `nus activate nu`, as the root README describes.

The tasks are also published as the OCI task catalog `ghcr.io/notlabs/nusage-tasks`, for a project with its own `[_.nusage.catalog]` entries: `[task_config] includes = ["oci::ghcr.io/notlabs/nusage-tasks:<version>"]`.
They need `nus`, `nu`, `mise` and `usage` on PATH; a `clap` entry also Cargo and rustfmt, an `openapi` entry `openapi-usage`.
The catalog calls the producers through the same task aliases in the checkout and in the OCI catalog: `nusage:clap:spec`, `nusage:schemas:overlay`, `nusage:schemas:examples`, `nusage:schemas:validate` and `nusage:report:emit`.
Schema validation takes JSON case results on stdin (`id`, `stdout`, `stderr`, `exit_code`); the suite owns the expected exit codes and schemas, while each tool's check owns its fixture and environment.
The producers' packaging tasks export these interfaces with their private implementation.

## Release

A checked main commit releases each entry whose `catalog/<tool>/v<version>` has no release yet: the archive `//catalog:pack` writes, and its packslip signature.
When `catalog_version` under `[vars]` has no `catalog/v<version>` release, the task catalog is pushed to GHCR at that version.
