# The catalog

Typed Nushell commands for other tools, generated by nusage from each tool's usage spec, the
schemas of its outputs and the overlays beside it. A module package per tool under `lib/`;
the entries in `mise.toml` under `[_.nusage.catalog]`; the tasks in `tasks/`, whose
`catalog.nu` documents a package's layout. `clap/` and `cobra/` read the spec of a binary
that ships none from its own library, and `schemas/` runs an output-schema suite.

## Use it

Each entry with a `version` is released as the packslip package
`github.com/notlabs/nusage/catalog/<tool>`, which records the mise tool and version its spec
was read from. A project installs the packages it uses, pins the tools they wrap at those
versions, and includes nusage's fragment:

```toml
include = ["git::https://github.com/notlabs/nusage.git//nusage/conf.d/nus.toml?ref=v0.2.0"]

[tools]
"github:notlabs/nusage" = { version = "0.2.0", version_prefix = "v" }
"packslip:github.com/notlabs/nusage/catalog/jj" = "0.2.0"
jujutsu = "0.46.0"
```

A script then calls the commands without importing them:

```nu
#!/usr/bin/env nus
jj log --revision ["@"] | first | get change_id
```

A call whose first word is a package's gets `use <module> *` before the script; a package
whose tool the project has at another version than it was generated from is refused, and
`^jj` is still the binary. The include also makes `nu` the `nus nu` wrapper; run `mise reshim`
after adding it. An interactive session imports a package itself, by the path `mise where`
gives.

The tasks are also published as the OCI task catalog `ghcr.io/notlabs/nusage-tasks`, for a
project with its own `[_.nusage.catalog]` entries: `[task_config] includes =
["oci::ghcr.io/notlabs/nusage-tasks:<version>"]`. They need `nus`, `nu` and `usage` on PATH;
a `clap` entry also Cargo and rustfmt, an `openapi` entry `openapi-usage`.

## Add an entry

1. Declare it in `mise.toml`, with how to get its spec: `spec = { run = "…" }`, a command
   that prints it; `spec = { clap = "spec" }`, an extractor under the package, as
   `clap/README.md` describes; or `spec = { openapi = "openapi.yaml" }`, a service's OpenAPI
   document. `switch` names the flag that selects structured output, when the spec declares
   no `output`. A `run` that builds something adds `probe = "version"`, so `check` compares
   the spec's `version` with `<bin> --version` instead of exporting again.
2. `mise run //catalog:spec <tool>` writes `lib/<tool>/<tool>.usage.kdl`, and for a service
   `<tool>.http.kdl` and `schemas/`.
3. Add `lib/<tool>/*.overlay.kdl` for what the spec lacks: types, outputs, selectors. They
   merge in name order. A suite under `lib/<tool>/schemas/`, as `schemas/README.md`
   describes, declares outputs with their schemas instead.
4. `mise run //catalog:generate <tool>` writes `lib/<tool>/mod.nu`; commit it with the spec.
5. Add `lib/<tool>/check.nu`, run with `lib` on the include path, and `nupm.nuon`.
6. Give the entry a `version`, and `tool`, the mise tool of its binary, to release it.

`mise run //catalog:check` holds every entry's committed files to its inputs, and its spec to
the tool on PATH.

## Release

A checked main commit releases each entry whose `catalog/<tool>/v<version>` has no release
yet: the archive `//catalog:pack` writes, and its packslip signature. When `catalog_version`
under `[vars]` has no `catalog/v<version>` release, the task catalog is pushed to GHCR at that
version.
